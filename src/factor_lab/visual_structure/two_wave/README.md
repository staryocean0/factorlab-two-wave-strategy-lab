# Two-Wave implementation modules

This package contains both the current Development representation chain and historical versioned research implementations needed to reproduce formal conclusions.

## Current reusable Development chain

The current representation/transplant sequence is:

- v0.7.1 F3 persistence-dominant semantic objectization;
- v0.7.4 prefix-causal lifecycle;
- v0.7.5 immutable provisional lifecycle publication;
- v0.7.6 v0.6.18 qualification transplant;
- v0.7.7 D1/v0.6.25 direction transplant.

`repository_consistency.py` maintains and validates the current v0.7.8 repository authority boundary.

These modules support Development/reproducibility work only. They do not install semantic-parent, direction, trading, or production authority.

## Historical modules

Older v0.5.x, v0.6.x, and v0.7.0–v0.7.3 modules are intentionally retained when a formal protocol/result depends on them. Do not delete a module merely because a later stage superseded its scientific authority; historical reproducibility and current authority are different concerns.

A versioned filename is not an authority signal. Always read `experiments/two_wave_m0_authority.json` and the referenced formal protocol/RESULT/ADJUDICATION.

## Change discipline

- Preserve causal-prefix semantics.
- Do not silently change a historical helper that is needed to reproduce an old result; add a new versioned adapter when semantics change.
- Do not tune representation, qualification, or direction thresholds using held-out/reference outcomes unless a frozen protocol explicitly permits it.
- Keep immutable publication identity rules explicit and tested.
